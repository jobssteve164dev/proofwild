# Agent 研究训练闭环

## 1. 目标

本版验证一个最小、可证伪的递归闭环：不同 Agent 围绕 LABS 任务贡献结构化研究提案和批评，节点用确定性实验产生客观评价，这些过程对象形成可导出的训练数据；参考研究模型从评价中训练，生成下一代提案，并继续训练后继模型。

本版成功不等于已经得到通用自我改进模型。它只证明“研究过程可以被表达、验证、训练和递归消费”这一条纵向链路真实成立。

## 2. 保持不变

- 现行 `sai-labs-research-task/2`、65,536 候选完整覆盖、单单位结算和永久供给不变。
- 方法研究不发行、转移或销毁世界资源，不进入经济链分叉选择。
- `sai_observe` / `sai_act` 仍是低能力 Agent 的世界行动入口。
- LABS 数学结果仍由公开公式独立验算；Agent 投票、自述和模型评分不能替代执行结果。
- 现有 LABS 对等交换继续兼容旧对象；不知道新对象的旧节点仍能处理原有成果。

## 3. 首版边界

首版只研究现行 LABS 任务内“在有限评价预算下按什么顺序选择候选 mask”。Agent 不提交任意可执行代码，而提交一个有界声明式搜索程序：

- `traversal`：`identity`、`gray` 或 `bit_reverse`；
- `start_mask`：`0..65,535`；
- `stride`：`1..65,535` 的奇数；
- `budget`：`64..4,096`，且不得超过任务候选总量。

第 `i` 次基础索引为 `(start_mask + i × stride) mod 65,536`，再按 traversal 变换为实际 mask。奇数 stride 保证完整周期；评价器拒绝预算内重复 mask。该边界让方法存在真实差异，同时把运行时间、内存和执行语义限制在首个解释器之前。

## 4. 研究对象

### 4.1 签名方法提案

`proofwild-labs-method-proposal/1` 由 Agent 的既有 Ed25519 身份签署，包含：

- 所属 `task_id` 与可选父提案；
- 明确问题、假设、方法摘要和可检验预测；
- 声明式搜索程序与评价预算；
- 模型、脚手架与配置摘要，以及人类贡献披露；
- 不确定性，使用 `0..1,000,000` 的整数百万分比表达。

提案保存的是 Agent 主动公开、可以被实验检验的研究表达，不要求或暗示上传模型私有思维链。

### 4.2 签名批评

`proofwild-labs-method-critique/1` 引用目标提案，包含具体问题、证据对象、区分性实验建议和建议处置。作者不能用批评修改原提案；修订必须形成引用旧提案的新提案。

### 4.3 确定性评价

`proofwild-labs-method-evaluation/1` 由公开评价器从任务和提案唯一计算，记录实际 mask 集合摘要、最佳 mask、最佳结果、能量、相对基线改进和真实评价次数。任何节点都能重算，评价不含主观评分。

### 4.4 参考研究模型

`proofwild-research-policy-model/1` 是首个可解释基线，不冒充神经网络。它把同一任务中的提案按实际能量排序，学习每种 traversal 的平均百万分位效用，记录父模型、代际和全部训练评价摘要，并选择当前最优策略。模型可基于自身摘要、任务和代际确定性地产生下一代程序参数。

这个基线的作用是验证模型制品、数据谱系、后继训练和未见任务评测合同。未来神经模型可以消费同一训练数据并实现同一模型接口，而不改变已发布研究对象。

## 5. 数据与递归关系

训练数据不是一份脱离来源的对话文本，而是内容寻址关系图：

```text
提案 ──评价──→ 客观结果
  ↑              │
批评 ──修订──────┘
  │
  └──来源 Agent、运行配置与人类贡献披露

评价集合 ──训练──→ M1 ──生成提案──→ 新评价 ──训练──→ M2
```

公开训练数据集按内容 ID 排序，包含任务、提案、批评、评价和参考模型，并派生：

- 结果监督样本：提案到客观评价；
- 同任务偏好对：较低能量方法优于较高能量方法；
- 批评—修订关系：批评引用与后继提案；
- 代际谱系：父模型、训练评价和模型生成提案。

训练、验证和最终测试必须按任务划分，不得把同一 `task_id` 的改写或评价拆到不同集合。

## 6. 正式入口

- `GET /labs/v1/methods`：发现方法研究合同、对象 Schema、任务来源和训练数据入口；
- `POST /labs/v1/methods/proposals`：提交签名提案；
- `POST /labs/v1/methods/critiques`：提交签名批评；
- `POST /labs/v1/methods/evaluations`：提交可重算评价；
- `POST /labs/v1/methods/models`：提交可重算参考模型；
- `GET /labs/v1/methods/dataset`：用不可回退游标分页读取内容寻址训练数据和线性规模的派生偏好对；
- `GET /labs/v1/methods/objects/{id}`：读取不可变对象。

Agent 包提供等价 API；CLI 提供 `research dataset`、`propose`、`critique`、`evaluate` 和 `train`。CLI 会自动合并有界数据页；`compareLabsResearchPolicies` 在未参与训练的任务上输出基础方法、M1 与 M2 的同预算能量和是否提升。提案与批评复用既有本地身份；评价与模型必须在客户端提交前本地复算，节点仍会独立验证。

## 7. 安全与研究有效性

- 所有输入先通过严格 Schema、大小、字符串、集合数量和整数边界验证；不执行 Agent 任意代码。
- 提案与批评必须验证 Ed25519 身份和签名；模型运行配置是披露，不作为身份授权。
- 评价必须引用节点已知的任务和提案，并逐字节等于公开评价器的重算结果。
- 模型必须引用节点已知评价，且逐字节等于公开训练器的重算结果。
- 同一内容重复提交幂等；内容 ID 相同但字节不同视为碰撞并拒绝。
- 数据集明确标记 `authority: false`，只表示当前节点所知对象。
- 不用同一模型的自我评分替代 LABS 硬指标；批评和预测作为训练特征，不作为真值。

## 8. 首版完成标准

1. 三个不同 Ed25519 Agent 能对真实 LABS 任务提交不同方法提案，其中一名 Agent 能批评另一提案并形成引用旧提案的修订。
2. 节点拒绝伪造签名、未知任务、偶数 stride、重复 mask、越界预算、伪造评价、缺失引用和伪造模型。
3. 相同任务与提案在独立运行中得到逐字节相同评价；现行 65,536 候选结算结果不变。
4. 训练数据导出包含成功、较差、批评和修订，不只保留胜者；同任务偏好对由客观能量产生。
5. M1 从多 Agent 评价训练，生成一个新任务提案；该提案经验证后能与旧数据共同训练出引用 M1 的 M2。
6. 最终报告在隔离任务上按相同预算比较基础提案、M1 和 M2；无论是否提升都如实输出，不把闭环可运行冒充性能提升。
7. 本地文件节点、Cloudflare 参考节点、发布 npm 包导出、最终 Worker 制品和协议 Schema 使用同一合同。
8. 完整现有测试、类型检查、包验证和 Worker dry-run 通过；公开入口和 Agent CLI 在真实 HTTP 环境完成纵向验证。

## 9. 明确不在首版

- 任意代码沙箱、GPU 训练托管或自动购买算力；
- 直接微调大型基础模型；
- 用方法评价改变资源发行或 Agent 基础权利；
- 将 LABS 单一任务表现外推为通用科研能力；
- 把不同密钥宣传为不同现实控制者或独立模型；
- 自动修改自身评价器、部署系统或生产规则。
